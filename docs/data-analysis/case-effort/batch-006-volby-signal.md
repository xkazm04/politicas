## 1. Access assessment — confirmed, with corrections to batch-005's framing

Batch-005's ACCESS ASSESSMENT (§1 of `batch-005.md`) said volby.cz/ČSÚ Open Data was free, no-auth, bulk-downloadable and carried `POVOLANI`. Re-verified directly this batch (actual download, not just the index page):

- **Index page**: `https://volby.gov.cz/opendata/ps2025/ps2025_opendata.htm` — confirmed free, no auth, no rate limit.
- **Actual registry file** (not documented on the index page itself — required a bounded probe, per the kernel's enrich-stage doctrine): `https://volby.gov.cz/opendata/ps2025/PS2025reg20251005_csv.zip` (330 KB). Unzips to `csv/psrk.csv` (the candidate list, 4,475 candidates) + `csv/psrkl.csv` (party/list registry, 26 lists) + a `psrkl_slozeni.csv` composition table (coalition membership) + a `csv_od/` mirror with `.json` siblings.
- **Format correction to batch-005**: the file is **semicolon-delimited RFC4180-style CSV with `""`-escaped quoted fields**, windows-1250 encoded — **not** the psp.cz UNL pipe format the rest of this repo's adapters share. This matters operationally: a naive `line.split(";")` silently corrupts rows. Proven on a real row in the live data — Zdeněk Hřib's own `POVOLANI` text contains a literal `;` (`"...stavějící metro, tramvajové tratě a mosty; hrdý obyvatel..."`), which shifts every later column of that row under a naive split. `lib/ingest/sources/volby.ts` ships its own small quote-aware CSV scanner (`parseCsv`) rather than reusing `../unl.ts`'s pipe/backslash parser, and `volby.test.ts` has a dedicated regression test using this exact real row.
- **Field shape**: `psrk.csv` columns (0-indexed) — `VOLKRAJ;KSTRANA;PORCISLO;JMENO;PRIJMENI;TITULPRED;TITULZA;VEK;POVOLANI;BYDLISTEN;PSTRANA;NSTRANA;PLATNOST;POCHLASU;POCPROC;MANDAT;SKRUTINIUM;PORADIMAND;PORADINAHR`. **There is no separate employer field** — `POVOLANI` is free text and sometimes names an employer inline ("ředitel společnosti X"), sometimes is a bare job title. `MANDAT="A"` marks a winning candidacy (199 of 4,475 rows, matching the 200-seat chamber minus one row corrupted by the same embedded-`;` class of bug quoted above — see §4).
- **`VOLKRAJ` region codes** are not documented on the page; verified against real rows this batch (VOLKRAJ=10 → Josef Kott's own Vysočina candidacy; VOLKRAJ=1 → a real elected Prague MP's candidacy) to be the standard ČSÚ 14-kraj numbering. Hardcoded as `VOLKRAJ_NAME` in the adapter with that provenance noted in a comment.
- **Licence**: ČSÚ open data, free, no ToS friction; snapshot dated "as of 2025-10-05" (PS2025 registration close), no diff feed — re-sync only makes sense at the next election, same refresh cadence as the existing `osoby.unl` registry ingest.

## 2. Build — `lib/ingest/sources/volby.ts` (+ `volby.test.ts`, 19 assertions, all pass)

Follows the house adapter convention (`psp.ts` / `psp-activity.ts` / `psp-legislation.ts`): pure parse/normalize functions over already-fetched bytes, no network call inside the adapter itself (the actual `fetch()` + on-disk caching belongs to an ingest script, same split as `scripts/data-analysis/ingest.ts` vs `lib/ingest/sources/psp.ts` — not built this batch, out of the file boundary; the adapter is fetch-ready with `VOLBY_REGISTRY_CSV_ZIP` exported as the exact URL to fetch).

Exports:
- `parseCsv` — the quote-aware CSV scanner described above.
- `parseCandidates` / `CandidateRow` — typed candidate rows, `VOLKRAJ` resolved to a region name.
- `parsePartyLists` / `PartyListRow` — the party/list registry (`psrkl.csv`).
- `normalizeCandidates(psrkCsvBytes, psrklCsvBytes?)` — the IO-shaped bundle an ingest script would call.
- `joinCandidatesToMps(candidates, mps)` — name+region(+MANDAT tiebreak) join to any `{pspId, name, region?, club?}` roster; every result is `"matched" | "ambiguous" | "unmatched"`, never a silent guess.
- `isSelfReferentialOccupation` — detects `POVOLANI` text that just names the candidate's own current office ("poslanec…", "ministr…") rather than an outside tie.
- `classifyEmploymentCoi` — the deterministic Kott-class classifier: word-boundary (never substring) stem-match between `POVOLANI` and the sector a committee the MP actually sits on oversees.

`npm run check` scoped to what was touched: `npx tsc --noEmit` clean repo-wide; `npx eslint lib/ingest/sources/volby.ts lib/ingest/sources/volby.test.ts` clean; `npx vitest run` — **26 test files, 259/259 tests pass** (19 of them new, in `volby.test.ts`), repo-wide, at the time this batch ran. (Per batch-005's own lesson, this is a point-in-time snapshot in a fleet run — a sibling case could still drop an untracked file into the shared tree after this was measured.)

- **Unmatched (2): Zuzana Mrázová, Michaela Řehková.** Neither surname appears anywhere in the 4,475-row PS2025 registry under any spelling variant tried (`mrázová`/`mrazova`, `řehková`/`rehkova`) — not a join-logic failure, a genuine absence in the source. The most likely explanation is a surname change between the October 2025 candidacy and the current psp.cz person record (marriage/divorce), but that is a hypothesis, not verified against a third source — flagged here rather than asserted. **Not silently dropped**: both are reported by name so a future pass can chase the actual explanation (e.g. cross-check psp.cz's own `zmena` column, which exists for exactly this class of change).
- **Zero ambiguous, but only after fixing a real collision the region-only join could NOT resolve**: two different "Miroslav Krejčí" candidacies are both filed in **the same region** (Jihočeský, different party lists) — region alone left them tied. `joinCandidatesToMps` was extended with a second tiebreak: when a same-region collision remains, and exactly one of the tied candidates actually won a mandate (`MANDAT="A"`), that is the disambiguator (a sitting MP must have won a seat under some candidacy). Both the original region case (Zajíčková, Praha vs Zlín) and this MANDAT-tiebreak case are covered by dedicated tests, including a test that the join still reports `"ambiguous"` rather than guessing when even the MANDAT tiebreak leaves more than one candidate tied.
- Join key is name+region only (no shared person id exists between volby.cz and psp.cz, as batch-005 already flagged) — the same join-risk class as every other cross-source join in this repo. 99.0% resolution on a real population is a strong result for that risk class, but it is a name-based join and should be treated as such (no birth-year field exists in the candidate registry to cross-check against).

## 4. The Kott-class signal — real yield, honestly measured

**Self-referential occupation is the headline structural finding.** Of the 205 matched candidacies, **108 (52.7%) self-declared their `POVOLANI` as their own current office** — "poslanec PSP ČR", "ministryně obrany České republiky", etc. — via `isSelfReferentialOccupation`. This is a genuine, load-bearing limitation: PS2025 was fought mostly by incumbents seeking re-election, and an incumbent's own PS2025 registration overwhelmingly names the office they already hold, not the outside business/employment tie that predates it. **This directly defeats the signal for exactly the MPs the Kott class targets** — see below.

**Josef Kott's own PS2025 record: `POVOLANI = "poslanec PSP ČR"`.** He is a member of `ZEV` (Zemědělský výbor / Agriculture Committee) and vice-chair of `KV` (Kontrolní výbor / Control Committee) — precisely the committee combination the "Kott/Agrofert/Control-Committee class" in the effort-loop skill describes. **The classifier returns zero hits for Kott.** Not because the logic is wrong, but because the ONE source this batch was tasked with building (volby.cz) structurally cannot see it: his declared occupation is his own current mandate, not whatever employment tie predates it. **This is the null result reported honestly, not manufactured.** cro.justice.cz — the source that WOULD carry his actual pre-mandate business/employment history — remains the human-mediated-only path batch-005 already ruled out for autonomous access.

**Deterministic classifier yield (excluding self-referential occupations)**: **33 sector-committee hits across 32 unique MPs** (one MP, Pavel Žáček, hits twice — both `VO` and `VB`, a genuine defense/security occupation-committee double match) — **15.6% of the 205 joined MPs**. By sector: `education_science` 7, `public_admin` 7, `health` 6, `law` 5, `business_economy` 4, `defense_security` 2, `media` 1. (`agriculture`, `environment`, `finance_budget` scored **zero** real hits — a genuine finding, not a coding gap; the classifier's own test suite proves those sectors DO fire on synthetic input.)

**The combined "Kott-class" severity signal (sector-committee match AND simultaneously on the Control Committee, `KV`) fires for exactly 3 MPs**: Jiří Pospíšil (law/`ÚPV` + `KV`), Jiří Svoboda (business_economy/`HV` + `KV`), Jiří Penc (health/`VZ` + `KV`). These are **structural-overlap leads, not accusations** — sitting on both an oversight committee and a sector committee whose remit matches one's declared occupation is exactly the pattern the class describes, but `classifyEmploymentCoi` does not (and structurally cannot) verify an actual conflict; it flags a class of situation worth a human-gated dossier look, same as every other web-research lead in this loop.

**False-positive risk, measured**: the classifier uses `\b`-anchored stem matching specifically to avoid the P42 substring-collision class ("vydání" containing "daní"). `volby.test.ts` has a dedicated regression using a REAL Czech negation-prefix case found while building this: `"nefinanční poradce"` (a non-financial advisor) folds to `"nefinancni poradce"`, which contains the `financn` stem as a mid-word substring (preceded by the negation prefix `ne-`, not a word boundary) — a bare `.includes()` classifier would have wrongly tagged a non-financial advisor as a finance-sector tie. The `\b` anchor correctly excludes it; verified live against the real 205-MP population (no false "nefinanční"-class hit appears in the 33 real hits above).
